## Решения, которые нужно сохранить

- Неполная карточка — черновик; полностью пустая карточка не сохраняется; повторное сохранение не создаёт второй контракт.
- Отдельной приёмки и её таймера нет. После вручения контролируется единый срок оплаты.
- «Вручен» и «Исполнено» различаются; окончательное исполнение требует оплаты.
- Списание идемпотентно: отправка уменьшает склад один раз, вручение/оплата не повторяют списание.
- Закупка и отложенная закупка задаются по товарным позициям.
- Документы необязательны; нужны удобное открытие, выгрузка и читаемый список.
- Склад и главный экран должны показывать согласованные значения резерва; отрицательный остаток означает нехватку.
- Источник истины для количества/цен/контрактов — актуальная рабочая база или свежий архив, а не старый скриншот и не временный файл.
- Подробные правила дальнейшей разработки — в `AGENTS.md`.

## Данные и восстановление

| Назначение | Путь |
| --- | --- |
| Рабочая база Windows | `%LOCALAPPDATA%\UchetZakupok\zakupki_work.db` |
| Переопределение рабочего каталога | Переменная `ZAKUPKI_LOCAL_DATA` |
| Копия для синхронизации | `<папка EXE>/data/zakupki.db` |
| Вложения | `<папка EXE>/data/attachments` |
| Архивы | `<папка EXE>/data/backups` |
| Лог | `<локальный каталог>/app_debug.log` |

Для диагностики данных предпочтителен ZIP, созданный в работающем приложении через «Файл → Создать резервную копию сейчас».
До замены базы нужно сохранить оригинал и проверить актуальность копии. Не восстанавливать старый архив поверх более новых изменений.

## Текущий режим автоматического резервирования (25.11.2026)

**Статус:** испытательная программа, не переносите в неё реальные контракты до полной сверки Excel.

Встроенный сервис `backup_policy.py` создаёт **полный проверенный ZIP с SQLite, вложениями и Корзиной** не чаще 1 раза в 24 часа при работающей программе. Если данные не изменились, новый архив не сохраняется; даже без изменений точка восстановления обновляется через 7 дней. Успешная новая проверка разрешает удаление **только автоматических копий** `backups/automatic/auto-*.zip` старше **14 суток**. При сбое создания архивов прежние не удаляются. Ручные ZIP и копии перед миграциями сохраняются отдельно.

Реальные пути упакованного приложения:
- Windows: `%LOCALAPPDATA%\ContractsIPSqliteLab\lab.db`
- macOS: `~/Library/Application Support/ContractsIPSqliteLab/lab.db`
- Документы: `managed_files/` и `attachments/` рядом с базой.
- Локальные полные резервные архивы: `backups/automatic/` внутри каталога данных.

Для дополнительного физически независимого источника можно настроить существующую папку через `CONTRACTS_SQLITE_LAB_SECONDARY_BACKUP_DIR`. Убедитесь, что это действительно другой SSD/NAS, а не другой раздел того же устройства. Пока этот параметр не задан, интерфейс явно сообщает **«внешняя копия не настроена»**. При отказе всего компьютера локальный backup на том же устройстве недоступен.

**Восстановление при сбое:** сначала взять архив с внешнего устройства, а при повреждении только БД — из локального `backups/automatic/`; выбрать его при первом запуске или открыть восстановление отдельной папки при ошибке старой базы. После проверки ZIP/SQLite/документов новый каталог готов к дальнейшему безопасному переключению. Никакая существующая база автоматически не заменяется. ZIP не шифруется.

Для независимого списка выполненного и оставшегося откройте [аудит покрытия требований и тестов](BACKUP_POLICY_AND_SQLITE_AUDIT_2026-11-25.md). Рабочий релиз должен обязательно пройти `python sqlite_build_safety.py --require-safe` на фактически упакованном SQLite и все миграционные/сквозные тесты. Тестовые EXE/.app без подписи не предназначены для учёта.

# Защита документов в SQLite LAB — актуальная реализация

> Это изолированная лаборатория будущего приложения «Контракты ИП».
> Рабочая Excel/Web-версия на 8765 не меняется. Реальные документы
> не импортировать до согласованной миграции и полного аудита.

## Файлы и внутренняя Корзина — 30 суток

- SQLite v4: таблицы `managed_files` и `file_events`, хранение файлов по непрозрачным ID; удаление переводит состояние в `trashed`, а байты сохраняются.
- Срок восстановления: **ровно 30 × 24 часа UTC** с момента удаления. Проверка очистки выполняется при загрузке интерфейса, а также каждый час, пока приложение работает. Если программа выключена, очистка проводится при следующем запуске/обращении.
- После истечения 30 суток содержимое managed-файла удаляется, а журнал действий и метаданные (статус `purged`) остаются для аудита. **Не удаляются** контракты, финансовые проводки и события склада.
- Исходные вложения из папки `attachments/`: безопасное помещение в Корзину означает **копирование → SHA-256 → регистрацию → пометку → удаление оригинала**. Восстановление возвращает файл в управляемые документы с его логическим относительным именем. Физическое восстановление поверх прежнего пути не выполняется, файл доступен для скачивания.
- Файлы вне папок приложения, удаляемые Finder/Проводником или внешними программами, не перехватываются.
- Лимит одного файла — 256 МБ, ZIP — 2 ГБ/10 000 записей.
- **Внешние ZIP/резервные копии не очищаются автоматически.** ZIP не шифруется; хранить его защищённо. На SSD и в ранее сделанных снапшотах безвозвратное физическое стирание не гарантируется.

## Полный архив Windows/macOS

В лабораторном браузере кнопка **«Экспорт: база + документы + Корзина (ZIP)»** создаёт проверенный архив с SQLite, остатками, операциями, финансовыми расходами, `attachments/`, активными и ещё восстанавливаемыми удалёнными файлами. Перед подтверждением архива сверяются SHA-256, размер и реестр.

На **первом запуске** Windows EXE или macOS .app предлагается восстановить ZIP *до* создания пустой базы. В новый каталог загружаются `lab.db`, `attachments/`, `managed_files/` и маркер успешной проверки. Существующая установка не заменяется; восстановление при наличии БД выполняется только в отдельную папку, без автоматического переключения.

CLI для тестовых данных (из каталога `web_sqlite_lab`):

~~~sh
python portable_transfer.py export --data-root ./data --output /path/to/new-transfer.zip
python portable_transfer.py verify --archive /path/to/new-transfer.zip
python portable_transfer.py restore --archive /path/to/new-transfer.zip --new-data-root /path/to/NEW-EMPTY-PATH
~~~

`--new-data-root` должен указывать на **отсутствующий каталог**.

CI: `web-sqlite-lab-ci.yml` — Python-тесты Windows/macOS/Linux;
`web-sqlite-lab-build.yml` — Windows EXE и macOS Intel/ARM .app и браузерная проверка;
`web-sqlite-cross-os-transfer.yml` — обмен полноценным **синтетическим** ZIP между разными GitHub Actions runners Windows→macOS (Intel/ARM) и macOS→Windows, с контрольной проверкой контракта, расходов, склада, активных/удалённых файлов и восстановлением. Это не подтверждение запуска на пользовательских компьютерах.

## Ограничения

Это **не миграция всей Excel-Web-программы**. Полная исходная книга, её формулы, PDF-письма, все внешние каталоги, старые процессы и пользовательские настройки не перенесены целиком и не проверены. Рабочая Excel остаётся источником истины; не использовать прототип для рабочих контрактов. VERSION и релизы не изменяются.

## Что действительно реализовано

- SQLite v1, внешние ключи, `WAL`, `synchronous=FULL`, `BEGIN IMMEDIATE`; запись контрактов и позиций одной транзакцией.
- Отдельные наименования товаров; приход с точной себестоимостью в копейках; физический остаток, резерв по заключённым неотгруженным контрактам, доступное количество, дефицит.
- Ревизии контрактов и идемпотентные operation IDs; конфликт при повторном ID с другим payload и при старой ревизии.
- При первом заключении автоматически фиксируется текущая дата по Москве, но указанная дата сохраняется и редактируется.
- Отправка списывает товары и оценочную средневзвешенную себестоимость **один раз**; переход из «Отправлен» в «Вручен» не списывает повторно. Запрещено отгружать физически отсутствующий товар и уменьшать чужие резервы.
- Снимок SQLite через online backup API: временный файл → закрытие соединения → `integrity_check` + `foreign_key_check` → SHA-256 → переименование без затирания архива. Локальная копия внутри lab/ на том же диске **не считается независимой резервной копией**.
- Простой браузерный интерфейс исключительно для тестовых контрактов, приходов и проверки снимков.

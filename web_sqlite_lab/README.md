## Граница и безопасность

Это новая браузерная ветка **отдельной Web-версии «Контракты ИП»**, а не настольный Tkinter/SQLite из основного репозитория. Исходная Web/Excel-система: `server.ps1`, `data/База_контрактов.xlsx`, локальный HTTP на **8765**. Новый эксперимент: `web_sqlite_lab/`, `server.py`, `store.py`, SQLite `web_sqlite_lab/data/lab.db`, **127.0.0.1:8766**. Нет чтения XLSX, файлов реальных контрактов и cloud-настроек; работающий порт 8765 не занят новым сервером. Никогда не направлять сюда настоящие пользовательские документы.

На ПК прототип расположен в отдельном `D:\ИП ПЕТРУШКИН С А\Контракты_ИП_SQLite_Lab\source\web_sqlite_lab`, а не внутри рабочего Web-каталога. Исходники также доступны в GitHub-ветке `feature/web-sqlite-parallel-prototype`. Действующая Excel-база, финансы, документы, сервер, релизы и VERSION не менялись.

## Запуск Windows / macOS / Linux

Требуется Python 3.11+; сторонние зависимости **не требуются**:

```sh
cd web_sqlite_lab
python -m unittest discover -s tests -p "test_*.py" -v
python server.py
```

В Windows также можно запустить **`start_lab.cmd`** из этого каталога: он открывает тестовый браузер и запускает независимый сервер на 8766; для остановки закрыть окно сервера/нажать Ctrl+C. Не запускать одновременно два экземпляра этой же тестовой базы.

Браузер: `http://localhost:8766/`. HTTP API доступен **только на loopback 127.0.0.1**, имеет обязательный случайный заголовок `X-Contracts-Key` для операций записи, лимит запросов 64 KiB и проверку Origin. Это базовая локальная защита, **не аудит**. Не публиковать порт через прокси, VPN или внешнюю сеть. Экземпляр единственный; конкурентные HTTP-вызовы сериализуются на уровне процесса + SQLite `BEGIN IMMEDIATE`.

Для отдельного автоматизированного теста разрешено указать временную БД через переменные окружения `CONTRACTS_SQLITE_LAB_TEST=1` и `CONTRACTS_SQLITE_LAB_DB`. Без тестового флага такой override отвергается.

## Что действительно реализовано

- SQLite v1, внешние ключи, `WAL`, `synchronous=FULL`, `BEGIN IMMEDIATE`; запись контрактов и позиций одной транзакцией.
- Отдельные наименования товаров; приход с точной себестоимостью в копейках; физический остаток, резерв по заключённым неотгруженным контрактам, доступное количество, дефицит.
- Ревизии контрактов и идемпотентные operation IDs; конфликт при повторном ID с другим payload и при старой ревизии.
- При первом заключении автоматически фиксируется текущая дата по Москве, но указанная дата сохраняется и редактируется.
- Отправка списывает товары и оценочную средневзвешенную себестоимость **один раз**; переход из «Отправлен» в «Вручен» не списывает повторно. Запрещено отгружать физически отсутствующий товар и уменьшать чужие резервы.
- Снимок SQLite через online backup API: временный файл → закрытие соединения → `integrity_check` + `foreign_key_check` → SHA-256 → переименование без затирания архива. Локальная копия внутри lab/ на том же диске **не считается независимой резервной копией**.
- Простой браузерный интерфейс исключительно для тестовых контрактов, приходов и проверки снимков.

## Что НЕ реализовано (не считать совместимостью)

- Импорт, экспорт и сверка фактической Excel-книги (пока нет, **никакой миграции**).
- Полное соответствие полям API/UX Web-приложения, справочникам, архиву/корзине, расходам, месячным и годовым финансам, всем настройкам УСН и налогов, движению по исправленному приходу.
- Все сценарии возвратов, повторных отгрузок после возврата, инвентаризации, пересчёта средневзвешенной истории; изменение отгруженной товарной строки сознательно запрещено до реализации корректного возврата.
- Устаревшие стадии и прямые переходы из произвольных статусов: лаборатория применяет упрощённую проверку переходов.
- Полная система документации и приложений (сопроводительные письма, PDF, КП, документы, подписи, сертификаты), двух внешних резервных источников и доказанного восстановления файлов.
- Проверка работы в macOS, автозапуск, упаковка Windows EXE, UI-кроссбраузерная регрессия, нагрузочные тесты и выпуск релиза.

**Важно:** в lab применён упрощённый расчёт резервов и стоимости; он ещё **не доказан эквивалентным** `Stock-Model` из действующей Web/Excel. Не менять действующую логику на эту экспериментальную до полной сверки.

Команда Windows: `python -m unittest discover -s tests -p 'test_*.py' -v`.
Один ранний прогон выявил WinError 32 в резервировании из-за незакрытого SQLite destination (исправлено). Второй выявил незакрытый тестовый SQLite handle (исправлено). Профиль тестового Chrome после финального прогона удалён. В ходе текущего этапа штатный lab-сервер также был запущен на localhost:8766: HTTP 200, integrity_check=ok, 0 реальных контрактов. Действующий Excel-сервер localhost:8765 проверен отдельно: HTTP 200, 10 контрактов; рабочие данные не изменялись. Ручная работа в обычном браузере пользователя и macOS ещё не подтверждена.

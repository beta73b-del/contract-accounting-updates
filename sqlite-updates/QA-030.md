# QA — ContractsIP SQLite 030 (28.11.2026)

База: опубликованная 029; локальная реконструкция прошла проверку 28 файлов интерфейса штатным `verify_ui`. Изменения: поле «Торговая площадка» в карточке контракта — обычный текстовый input с datalist прежних 12 значений и maxlength=120. Начальное значение «Сбер», существующая обязательность для завершённой карточки, правила черновика, серверная нормализация, хранение и отображение сохранены. Новые значения не добавляются в общий справочник автоматически. Миграция БД не нужна. Другие разделы не изменены. OTA требует именно 029 (`minVersion=29`), напрямую с 027/028 установка 030 несовместима.

Фактические проверки:
- Штатный updater.py: подготовка и установка 029→030, настоящий `server.py --validate-update` с HTTP-проверками, 28/28 файлов интерфейса; отдельный принудительный отказ и восстановление прежних файлов. SHA-256 базы и всех 48 документов не изменились в обоих испытаниях.
- HTTP API на изолированной копии: создание с новым названием, обрезка внешних пробелов, повторное чтение, редактирование на штатную площадку, 120 символов принимаются, 121 — отклонён с HTTP 400 без изменения записи, HTML-подобный текст сохранён буквально, пустая площадка — допустимый неполный черновик. Все существующие записи и документы неизменны. SQLite integrity_check=ok, foreign_key_check без ошибок.
- 3/3 новых Node.js-тестов (разметка, вызов оригинальной функции заполнения списка с 12 значениями, валидация и преобразование данных). Проверка синтаксиса Python и JS прошла. Полная регрессия старого набора из 019: 191/193 как до, так и после изменений. Два прежних теста конкурентов ожидают устаревшее скользящее окно, а с 026 используется шесть календарных месяцев с текущим. Новых падений нет. Эти тесты не редактировались.
- Chromium не прошёл навигацию из-за ERR_BLOCKED_BY_ADMINISTRATOR. Реальная проверка ввода в браузере и Windows EXE не выполнена. Рабочие файлы пользователя не изменялись.
